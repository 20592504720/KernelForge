# Architecture

The repository is organized around separate responsibilities: `configs/` describes inputs, `schemas/` defines accepted structure, `kernelforge/toolchains/` owns toolchain sources, downloads, hashes, safe extraction, locks, cache installation and maintenance, and `.github/workflows/` runs validation and later build jobs.

The build engine separates source acquisition (`kernelforge/source.py`), legacy system-tool inspection (`toolchain.py`), managed toolchains (`kernelforge/toolchains/`), and GKI/Vendor command adapters (`build.py`). Adapters accept explicit argv arrays and never pass through a shell. Each adapter may declare its own LLVM or GCC profile. The manager prepares a private environment overlay and report record; it never mutates the process-wide `PATH`. Download sources are extensible through source adapters; the built-in archive adapter requires explicit URL, format and SHA256 and does not assume a vendor-specific directory layout.

Downloads are serialized by a cache-key lock. Archives are streamed to unique temporary files, size-checked where configured, SHA256-verified against the profile, extracted with path traversal and link rejection, and installed by directory rename. Cache metadata is written last. Every cache use verifies metadata, archive digest, installed tree digest and the compiler version. A live build lease prevents cache cleanup during a build. Local profiles record a user-configured trust source and do not claim a trusted archive checksum.
